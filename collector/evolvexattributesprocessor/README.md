# Evolvex OTel Collector Extension (Feature #2)

Custom Go processor that enriches traces with Evolvex investigation context:

- `evolvex.incident_id`
- `evolvex.git_sha`
- `evolvex.deploy_version`
- `evolvex.namespace`
- `evolvex.sampling_mode` / `evolvex.sampling_rate`
- `evolvex.organization_id`

## Build into a custom collector

Use the [OpenTelemetry Collector Builder](https://github.com/open-telemetry/opentelemetry-collector/tree/main/cmd/builder):

```yaml
# collector/ocb-manifest.yaml
dist:
  name: evolvex-otelcol
  description: Evolvex collector with enrichment processor
  output_path: ./dist
  otelcol_version: 0.100.0

processors:
  - gomod: github.com/ishaansatapathy/evolvex/collector/evolvexattributesprocessor v0.0.0
    path: ./evolvexattributesprocessor
```

```bash
cd collector
builder --config=ocb-manifest.yaml
```

## YAML usage (generated by Evolvex API)

Set `TI_USE_GO_PROCESSOR=true` on the API to emit this processor block instead of the built-in `attributes` processor:

```yaml
processors:
  evolvexattributes:
    incident_id: "inv-123"
    git_sha: "abc123"
    sampling_mode: incident
    sampling_rate: "1"
```

## Fallback (no custom binary)

When the Go processor is not deployed, Evolvex falls back to the standard OTel `attributes` processor with the same keys — see `packages/services/telemetry-intelligence/collector/config-generator.ts`.
